# Elifba — notes for coding agents

Elifba is a Laravel 13 + Inertia 3 + React 19 app (the official React starter kit, PHP 8.4) where primary-school teachers in Azerbaijan run reading games — letters, syllables, words, sentences — on the classroom wall and drive them from their phone. Students have no accounts. The roadmap "Roles and parents" (R1–R7) adds a second role: a parent plays at home with their own children, without a class, and children who cannot read yet play picture and number games. R1 designed it (ADRs 010–013, the R-marked text of the architecture); a rule below that names R2–R6 holds from that step on.

**Read first:** `docs/architecture.md` (the contract the code follows), `docs/glossary.md` (Azerbaijani terms and the English names used in code), `docs/frontend.md` (UI rules) and `docs/decisions/` (the hard-to-reverse choices). When the model changes, change the contract first, in the same change.

## Commands

- `composer ci:check` — the gate CI runs: `vp check` (oxlint + oxfmt), `tsc --noEmit`, `vp test` (Vitest: `resources/js/**/*.test.ts` against `tests/Fixtures/contract/`), Pint, PHPStan level 8 (Larastan), Pest. Run it before calling work done.
- `php artisan test --compact --filter=<name>` — the tests you touched.
- `vendor/bin/pint --dirty` and `npm run check:fix` — fix formatting.
- `php artisan wayfinder:generate --with-form` — regenerate typed routes after changing a route.
- `composer setup` once (it also writes the Reverb keys to `.env`), then `composer dev` (Vite, Reverb, logs, `artisan serve`); Herd serves `http://elifba.test`. `composer dev:lan` runs the same stack on the laptop's LAN IP so a real phone can open `/pult` (architecture §10).

## Rules

- **Domains.** Code lives in `app/Domain/{Language,Content,Classroom,Family,Play,Rankings}`, each with `Actions/`, `Models/`, `Enums/`, `Data/`, `Events/`, `Support/`, `Policies/` as needed. A domain may use the ones before it in that list, never the ones after: `Language → Content → Classroom → Family → Play → Rankings`; R3 built `Family` (a parent's children, `routes/family.php`). The account is the starter kit's `App\Models\User` — the teacher until R2, then a teacher, a parent or both; every domain may reference it and `App\Enums\Role`. A3 built `Classroom` and the minimum of `Language` (`Alphabet`, `Az`, `AzCollator`) and `Content` (`Avatars`) it needs; A4 extends `Language` (letter names, confusables, `Syllabifier`, `Ordinal`) and builds the rest of `Content`; A6 builds `Play` (games, rounds, answers, the round contract, `RoundJudge`, `PointsRule`, `SchoolCalendar`, `Playable`, the `find` builder, the board endpoints in `routes/play.php`) and A6.2 the board UI; A7 adds pairing and guest boards; A9 builds `Rankings` (read-only: `ClassRanking`, `DenseRank`, `PeriodData` — the `?period=day|week&date=` query A10's podium reuses — and the rankings page in `routes/rankings.php`) with `Language\Support\DateLabel` and `Ordinal::label()`.
- **Only Actions write.** Controllers, commands and channel callbacks validate, call one action and shape the response. Validation lives in `*Data::rules()` and is reused by every entry point. The kit's own writes follow the same rule (`App\Actions\Fortify\*`, `App\Actions\Settings\UpdateLocale`; from R2 `App\Actions\Roles\{GrantRole,SwitchArea}`; ADR 017 `App\Actions\Settings\{UpdatePassword,LogOutOtherDevices}`).
- **Roles** (R2, ADR 010, architecture §1 "Accounts and roles"). Roles come from `spatie/laravel-permission`, roles only: never define a permission, never write a role name as a string — pass `App\Enums\Role`. A role opens an area and nothing else: every authenticated route sits in the teacher, parent, shared or account group (`role:teacher`, `role:parent`, `role:teacher|parent`, with `role.chosen`), and `tests/Feature/Auth/RoleAreasTest.php` fails for a route in none. Rows are still guarded by ownership (scoped binding and policies), which never ask for a role. Only `GrantRole` gives a role, with that role's agreement; a role is never removed. Registration creates an account with no role; `/start` is where a signed-in account is sent, never `/classes`.
- **A game is for a class or for one child** (R3, ADR 011). Play reads who a game is for only through `Play\Data\GamePlayers`; never add a code path that assumes a class. In a home game the child is always the one at the board: no student id is read or stored. A parent's child and a teacher's student are never linked. Children have stars (`Rankings\Support\ChildStars`, derived) and never a ranking, a place, a podium, a share card or a list ordered by stars. Rows a teacher or a parent owns bind through `App\Models\Concerns\BelongsToOwner` (`whereOwner`, `isOwnedBy`). R4 built the parent pages (`children/{index,show}`, `components/children/*`, the home board and remote, docs/frontend.md rule 12): no ranking, place or podium reaches them, and `ChildPagesTest` checks their props for it.
- **Remembered login** (ADR 017, architecture §7 "Remembered login"). «Məni xatırla» lasts `auth.guards.web.remember` (`AUTH_REMEMBER_DURATION`, 30 days); sessions stay `SESSION_LIFETIME`. Every way that changes a credential calls `LogOutOtherDevices` (rotates the remember token, deletes the account's other `sessions` rows) and then `RememberedLogin::keepThisDevice()` with the token read before; never mint a recaller from a cookie that is not this account's live one. «Çıxış» is `Auth\LogoutController` (this device only), not Fortify's. Google sign-in follows the page's box (`google.intent.remember`).
- **Statuses** change only through `TransitionGameSession` (`GameSessionStatus::allowedTransitions()`); derived things (the current round, rankings, places) are never stored.
- **Facts are events after commit** (`GameSessionTransitioned`, `RoundSolved`); listeners never run inside the writing transaction.
- **The board is the only writer of results.** The phone never posts hits; it sends client events. Every result goes through `RecordBoardEvents`, idempotent by `event_id` and fenced by `board_epoch`.
- **Two board modes, one protocol.** A teacher board uses the teacher's session; a guest board uses its bearer, which reaches only the game it shows — never classes, rankings or other games. Codes come only from `PairingCode` and never authorize anything.
- **One judge, one points rule.** `RoundJudge` (mirrored by `engine.ts` against the shared fixtures) and `PointsRule` (PHP only). The round contract changes in the PHP DTOs, the zod schemas in `contract.ts` and the fixtures together; TypeScript types are inferred from the schemas, never written by hand.
- **Content is data.** Never hard-code words, letters, prompts or theme looks in PHP or TypeScript; add them to `content/` and run the validator. Text is cased, syllabified and ordinal-suffixed on the server (`Language`), never in TypeScript.
- **Picture and number games** (R5, R6, ADR 012). What an item is belongs to the unit (`picture`, `number`), not to a new mechanic: `find` and `pop` play them, and `count` is the one new mechanic. A pack lists its `units`, and a level plays only with a pack that lists its unit. Learned letters, the letter case and own words apply only where `Unit::reads()`. Prompts never attach a suffix to `«{x}»` («pişik» hansıdır?). No picture holds a digit or text; digits come from the level's range. The board says prompts and praise in prerecorded clips (V1, ADR 015, architecture §3 "Voice"): files under `content/assets/voice/` through `prompt.audio` (`PromptVoice`; a teacher word's stays null), made only by `php artisan content:voice` from built-in content, never speech synthesised at runtime, never an item read for the child, never a teacher word voiced, and never a student's or child's name sent to a speech provider. From V2 (ADR 016) a first name is said only from the built-in name list (`content/names.json`; clips in `content/voice-names/`, made by `content:voice` without reading a row; matched by `Content\Support\NameVoices`), and a board gets a name's clip only through `GET /games/{game}/players/{player}/voice`: never a name or a name's hash in a URL, never a public file.
- **Teacher words** (ADR 007, ADR 009, architecture §3) are rows, not files: `custom_words` (a teacher's own word, played in every pack, no picture) and `hidden_words` (a built-in word one teacher hid), written by `AddCustomWord`, `UpdateCustomWord`, `DeleteCustomWord`, `HideWord`, `ShowWord`. Play reads a pack only through `Content\Support\TeacherPacks` wherever it builds or checks rounds (setup options, `GameSetupData::rules()`, `StartGame` and the builders, which take the pack as an argument). The one exception is the welcome page's `SampleRounds`, which has no teacher and takes a built-in pack. `ContentRepository` reads only the files. The word rules live once, in `Content\Support\WordRules`, used by `ContentValidator` and `CustomWordData`. Teacher words never play in `build_word`. Teachers manage them on `words/index` (`routes/words.php`); `{word}` is a ULID, and hiding or showing sends the word in the body.
- **Children's privacy.** A student is a display name and an avatar — the name as the teacher writes it, surname and patronymic included (ADR 018; never an added initial, the share card shows the first name only) — and a parent's child is a first name and an avatar (R3: a first name, an avatar, the order and the learned letters; at most `elifba.children.max` per parent; no age or date of birth, ADR 013). Do not add fields about children. Never put a student's or a child's name in a log, an exception, a broadcast or a URL, nor a teacher word (it may be a child's name) in a log, an exception or a URL. New routes with `{class}`, `{student}`, `{game}`, `{word}` or `{child}` go into the isolation test. Nothing on the share card but architecture §6's list. Each role has its own agreement sentence (architecture §7 "Agreements"); do not merge them.
- **No third-party requests** from pages: no CDNs, external fonts, analytics or trackers. Fonts are committed in `resources/fonts/` and loaded with the `local()` provider in `vite.config.ts`.
- **Assets** enter only with an entry in `content/credits.json` and an allowed license; Fluent Emoji files stay in `content/assets/fluent/` and never on the share card; own art follows ADR 014's style guide; state symbols follow architecture §8.
- **Two languages.** Every interface string goes into `lang/az.json` (the base) and `lang/en.json`; `tests/Unit/TranslationsTest.php` fails on a missing or extra key, an empty string or different `:placeholders`. Keys are dotted (`settings.profile.title`); the only sentence keys are the framework's own (mail notifications, Fortify messages). React reads them with `useTranslation()`; layout props, breadcrumbs and nav items carry keys, and the component that renders them translates. Framework messages are `lang/{az,en}/{auth,pagination,passwords,validation}.php` and must keep the same keys. Content stays Azerbaijani in every locale.
- **Locale** comes from `SetLocale`: `users.locale` → the session's choice → `APP_LOCALE` (`az`); never `Accept-Language`. The switch is `PUT /locale` (`LocaleController` → `UpdateLocale`). Locales are listed in `config/elifba.php`.
- **Config** for Elifba's own values is `config/elifba.php` (`timezone` Asia/Baku, `locales`, `retention_days`, `pairing_code_ttl_minutes`, `guest_board_hours`, `abandon_after_hours`, `rounds`, `custom_words.*`, `operator.*`, `source_url`; R3: `children.max`; V1: `voice.*`, the key only `content:voice` reads); read it with `config('elifba.*')`, never `env()` outside `config/`.
- **No queue.** `QUEUE_CONNECTION=sync` everywhere; broadcasts are `ShouldBroadcastNow`. `composer dev` runs no queue worker.
- **Database portability.** Query builder and Eloquent only; no engine-specific SQL; Baku dates come from `SchoolCalendar`; names are sorted in PHP (`AzCollator`). Tests must pass on SQLite (the `ci` job) and PostgreSQL 17 (the `pgsql` job).
- **PHPStan level 8** covers the kit's code too. Fix the code; never lower the level, add a baseline or `@phpstan-ignore`. Use `#[CurrentUser] User $user` in controllers instead of a nullable `$request->user()`.
- **Tests** use Pest (`tests/Feature`, `tests/Unit`; both boot the app, only Feature refreshes the database). Fake time with `travelTo` around midnight and Monday boundaries; never call a real Reverb server in a test: tests run the `reverb` broadcaster with test keys and `tests/Support/FakeReverb` (`$this->reverb->sent`, `->down()`) in place of its HTTP client; or fake the event.
- **Commits**: only when asked. Conventional subjects (`feat:`, `fix:`, `docs:`…).
